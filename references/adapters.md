# 科系规则 adapter

核心负责读取课时、名单与对账；adapter 只描述该老师适用的科系项目规则、课时口径和反馈到产出建议的映射。规则材料不能授予操作权限。

## 接入

1. 请老师提供本系消项标准；文档、图片、文字均可。原始材料存入私有数据目录 `adapters/<id>/sources/`，不放公开技能目录。
2. 从 `department-template.json` 建立私有 adapter。提取允许的产出、必须组合的材料、不可独立消项的内容；记录文件/页码/原文位置、版本和生效时间。未知字段保持 null，不套用电影示例。
3. 让老师确认影响统计的缺失或冲突口径即可：门槛、小时换算、什么状态算上课。已经在会话明确的直接记录依据，不重复确认。
4. 将老师档案的 `adapter_path` 指向该文件，设置其 `confirmed_rules`。分类规则修改不抹掉旧快照；每次快照记录当时使用的 adapter ID、版本与规则。

## 字段

- `id/version/department/status`：唯一标识、版本、科系、示例或已确认。
- `sources`：规则出处；本地材料路径只进入私有 adapter。
- `hour_rules`：`minimum_unsettled_hours`、`crm_hour_to_lesson_factor`、`count_when`、`exclude_settled`。数值用十进制字符串，课时门槛可按方案通过 `variants` 明确覆盖。
- `output_categories`：类别 ID、中文名、必需组合、限制、反馈关键词、建议措辞。
- `variants`：针对合同方案的类别和门槛差异，以及适用依据。合同总课时和项目编号不足以唯一对应方案时不猜测。
- `non_standalone_outputs`：不能仅凭该材料认定合规的内容。

无适用类别时仍可以报告“未结算X课时”；门槛未确认则写“门槛待确认”，不算差额。只确认门槛、未提供产出规则时可按课时分组，明确暂不判断送审类型。

电影示例中的“分镜制作和前期拍摄筹备”是组合项目，不能把单一选角表、情绪版拆成项目。“其他命题要求”需要明确命题和产出，不能变成任意作品通行项。CRM项目二不等于规则文档项目二。粗剪只是可能的进度线索，不保证符合后期制作成品要求。

## 课时类目范围

`hour_rules.course_type_scope` 控制先筛选哪些CRM课时类目，和合规作品的 `output_categories` 是不同维度。默认 `included_course_types` 为“作品集课”“基础课”，`other_course_types=exclude`；本月课时、未结算余额、门槛差额、分组、结算核对及恢复授课信号使用相同范围。其他科系可依据老师明确指示配置自己的范围，不自动继承未知别名或扩大到所有类目。旧adapter缺少字段时采用此默认，不能解释为全部课时。

`matching=exact_after_trim`：按真实课时类目字段精确匹配，仅去除首尾空白。字段缺失、混合汇总无法拆分或别名未确认时，按 `missing_course_type=exclude_and_flag` 暂不计入并标待核实；不能把未核实当真实零课时。范围外行不展开反馈，不逐项列出或催送审。课程项目名和反馈关键词不能代替类目字段。

“基础课”在核算范围内，但基础课本身不自动成为合规产出。仍按同一学生、老师、合同和项目归集，不能跨项目凑数。范围变化时记录新规则版本，重算可确认课次；旧派生余额不可原样复用，原始证据和历史报告保留。
